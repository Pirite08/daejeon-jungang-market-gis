# 보행 네트워크 검증 보고서

## 최종 네트워크 구성 방식

사용자가 Leaflet 웹 지도 위에서 직접 찍은 `network_nodes_edited (1).geojson`의 36개 노드를 기준으로 최종 보행 네트워크를 구성했다. 이번 단계에서는 Codex가 새 노드를 임의로 추가하지 않았고, 사용자가 찍은 노드만 사용했다.

연결은 단순 최근접 자동 연결이 아니라, 첨부 이미지에서 확인되는 실제 길의 흐름을 기준으로 다음 축을 나누어 수동 설계했다.

- 대전로797번길 상단 접근축
- 대전로791번길 생선골목/중앙시장 북측 축
- 대전로785번길 중앙시장 중심 축
- 대전로779번길 중앙종합시장·상가 축
- 중교로 및 남측 접근축
- 중앙로194번길·200번길·204번길 세로 골목축
- 대전로 동측 접근축
- 대전천 방향 서측 접근축

## 반영 파일

- `site/data/network_nodes.geojson`: 사용자 노드 36개
- `site/data/network_edges.geojson`: 최종 설계 엣지 61개
- `site/network-editor.js`: 네트워크 파일을 no-store로 불러오도록 수정
- `site/index.html`: `network-editor-8` 캐시 버전 적용

## 긴 엣지 처리

일부 95m 이상 엣지는 실제 지도에서 긴 도로 구간으로 보이는 곳만 유지했다. 해당 엣지들은 `confidence: medium`으로 낮춰 최종 보고서에서 검토 대상임을 드러냈다. 추후 현장 확인이나 추가 중간 노드가 가능하면 이 긴 엣지는 더 짧은 구간으로 분할하는 것이 좋다.

## 웹 검증

브라우저에서 다음을 확인했다.

- `network-editor.js?v=network-editor-8` 로드
- 네트워크 노드 36개 표시
- 경로 상태: `현재 경로: 보행 네트워크 기반 경로`
- 장보기 경로가 사용자 노드 기반 네트워크 위에서 Dijkstra 방식으로 계산됨


## 경로 최적화 알고리즘 개선

기존 방식은 `app.js`에서 직선거리와 점포 점수로 방문 순서를 먼저 정한 뒤, `network-editor.js`가 그 순서를 보행 네트워크 위에서 Dijkstra로 연결하는 구조였다. 이 경우 점포들이 같은 골목 주변에 몰려 있어도 방문 순서가 네트워크 흐름과 맞지 않으면 왕복·지그재그 동선이 발생할 수 있었다.

현재 방식은 `network-editor.js`에서 추천 점포 목록을 다시 받아 다음 순서로 보정한다.

- 출발지에서 가장 가까운 보행 네트워크 노드를 찾음
- 각 점포를 가장 가까운 네트워크 노드에 매칭함
- 각 품목군의 후보 점포를 네트워크 비용과 유형별 보정값으로 다시 평가함
- 네트워크 비용 기준으로 점포 조합과 최근접 방문 순서를 먼저 구성함
- 2-opt 개선으로 중간 구간을 뒤집어 전체 비용이 줄어드는 경우 순서를 갱신함
- 최종 구간은 Dijkstra 알고리즘으로 실제 노드·엣지를 따라 계산함
- 지도에는 굵은 선으로 보행 네트워크 본선을 표시하고, 점포 좌표까지의 짧은 접근은 점선 보조선으로 분리함

따라서 최종 동선은 단순 최단 직선 연결이 아니라, 사용자가 찍은 중앙시장 내부 보행 네트워크를 기준으로 방문 순서와 구간 경로를 함께 최적화한 연구용 장보기 경로이다.


## 9개 품목 상생형 검증

브라우저에서 과일·채소, 정육, 수산·건어물, 반찬·식료품, 떡·한과, 분식·먹거리, 카페·음료, 생활용품, 보건·약국을 모두 선택하고 `상생형`을 실행해 확인했다.

- 방문 점포 수: 9개
- 보행 네트워크 총 거리: 450m
- 예상 이동시간: 6.7분
- 경유 노드 수: 5개
- 방향 전환 수: 3회
- 검증 스크린샷: `route-optimized-final.png`

기존 화면에서 보였던 1,003m 수준의 우회 동선은 후보 점포 선택이 직선거리 기반으로 먼저 고정된 뒤 네트워크에 억지로 연결되면서 발생했다. 현재는 품목군별 후보 점포 선택과 방문 순서를 모두 보행 네트워크 비용으로 보정하므로, 같은 조건에서 훨씬 짧고 덜 복잡한 동선을 제시한다.

## 한계

이 네트워크는 사용자가 지도 위에서 직접 찍은 점과 첨부 이미지 해석을 바탕으로 만든 연구용 보행 네트워크이다. 공식 보행로 데이터나 현장 실측 데이터는 아니므로, 최종 산출물에서는 사용자가 직접 찍은 노드 기반 네트워크라는 점과 일부 긴 엣지의 검토 필요성을 명시해야 한다.
