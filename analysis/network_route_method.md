# 보행 네트워크 기반 경로 계산 방식

## 전체 흐름

장보기 품목군을 선택하면 기존 방식대로 후보 점포와 방문 순서를 먼저 정한다. 이후 보행 네트워크가 존재하면 각 구간을 점포 간 직선이 아니라 네트워크 노드 간 최단경로로 연결한다.

```text
출발지 → 가장 가까운 네트워크 노드 → Dijkstra 경로 → 점포 근처 노드 → 점포
```

## 점포와 네트워크 노드 연결

각 점포는 가장 가까운 네트워크 노드에 임시로 연결한다. 이 연결은 실제 통로가 아니라 점포 좌표와 보행 네트워크 사이의 접근 연결이다. 점포 좌표가 주소 기반 대표점일 수 있으므로, 실제 점포 출입구 위치는 후속 보정이 필요하다.

## Dijkstra 기반 구간 경로

출발 노드와 목적 노드 사이의 최단경로는 Dijkstra 알고리즘으로 계산한다. 엣지 비용은 경로 유형에 따라 달라진다.

- 빠른 장보기: `cost = length_m`
- 초행자 친화형: `cost = length_m + cognitive_cost_weight`
- 넓은 길 우선형: `cost = length_m + narrow_road_penalty - main_aisle_bonus`
- 상생형: `cost = length_m - inner_alley_bonus`

## 다중 목적지 방문 순서

여러 품목군을 방문해야 하는 경우, 현재 프로젝트는 기존 Greedy 방식으로 방문 점포 순서를 정한다. 이후 각 구간을 네트워크 최단경로로 연결한다. 추후에는 2-opt 등으로 방문 순서를 개선할 수 있다.

## 비교 지표

직선거리 경로와 보행 네트워크 경로는 다음 지표로 비교한다.

- 직선거리 총 거리
- 보행 네트워크 총 거리
- 거리 증가율
- 방향 전환 수
- 경유 노드 수
- 방문 점포 수
- 외곽부 점포 포함 수
- 예상 이동시간

보행 네트워크 기반 경로는 실제 이동 가능한 골목과 통로 구조를 반영하므로, 전통시장 내부 이동 현실성을 더 잘 설명할 수 있다.
