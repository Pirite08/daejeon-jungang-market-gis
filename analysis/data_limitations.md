# 데이터 한계

## 주소 기반 좌표 문제

현재 `stores.geojson`의 점포 좌표는 개별 점포 출입구 단위의 정밀 좌표가 아니라 주소 또는 건물 대표점 좌표일 가능성이 높다. 동일한 도로명주소 또는 동일 좌표에 여러 점포가 함께 배치되어 있으며, 한 좌표에 최대 75개 점포가 겹치는 지점도 확인된다.

## 좌표 중복 문제

좌표 중복은 지도에서 여러 점포가 한 지점에 겹쳐 보이는 문제를 만든다. 이는 실제 시장 내부에서 점포가 같은 위치에 있다는 뜻이 아니라, 원천 상가 데이터가 건물 또는 주소 단위 좌표를 공유하기 때문에 나타나는 현상으로 해석해야 한다.

## 보행 네트워크 부재

현재 프로젝트에는 실제 시장 내부 통로, 골목, 출입구, 교차점, 통로 폭, 혼잡도, 방향 전환 난이도 데이터가 없다. 따라서 현재 앱의 경로는 실제 보행 길찾기 결과가 아니라 점포 분포 기반 예비 동선 분석이다.

## 경로 해석의 한계

현재 경로 추천은 점포 좌표 간 직선거리를 사용한다. 실제 시장에서는 건물 내부 통로, 골목 연결성, 보행 가능 여부, 차도 횡단, 혼잡도, 시야 확보, 안내 표지판 등 다양한 요소가 이동 편의성에 영향을 준다. 그러므로 현재 결과를 실제 시장 내부 최단 보행 경로라고 표현해서는 안 된다.

## 후속 보완 방향

실제 검증을 위해서는 QGIS 기반 보행 네트워크 구축 또는 현장조사가 필요하다. 출입구, 교차점, 주요 통로, 점포군 대표 연결점, 편의시설 위치를 노드로 만들고, 실제 걸을 수 있는 통로를 엣지로 연결하면 네트워크 기반 경로 최적화가 가능해진다.
